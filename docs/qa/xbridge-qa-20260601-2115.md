## Bugs and Risks Found

### 1. Long-running read/export leaves pending result after client timeout

Severity: High

Observed:

- `/api/designer/read-context` timed out after 20 seconds.
- `/api/export-design-tokens` timed out after 25 seconds.
- Runtime later showed `pendingTotal=1`, `pendingResultsTotal=1`, then historical failed count increased.
- `npm run validate:streaming-first` failed with `Runtime ops still reports pending queue items after validation (1)`.

Impact:

- User sees inconsistent results: sometimes the bridge appears healthy, sometimes validation fails.
- UI may show stale or delayed output after the originating request is gone.
- Regression tests become flaky because queue cleanup is timing-sensitive.

Likely root cause:

- HTTP client timeout/connection close is not fully coordinated with queued command lifecycle and pending result cleanup.
- The command can complete after the response consumer is gone, leaving a result that validation treats as pending queue debt.

### 2. Validation script checks pending queue too aggressively

Severity: Medium-High

Observed:

- `npm test` failed once at `streaming-first validation defaults to an isolated plugin id when live sessions exist`.
- Isolated `tests/streaming-first-validation.integration.test.js` rerun passed.
- `validate:streaming-first` still failed when it created a temporary validation session and immediately checked runtime queue.
- `soak:quick` passed immediately after in a similar environment.

Impact:

- The release gate can report false negative or timing-sensitive failure.
- The user sees "오락가락" behavior even when transport itself is healthy.

Likely root cause:

- The validator asserts zero pending queue items before the command/result cleanup window fully closes.
- Temporary validation sessions add live-session noise to active session counts.

### 3. Multi-session ambiguity is normal but still too easy to misuse

Severity: High

Observed:

- Multiple Figma tabs/files are open.
- Health correctly reports `requiresExplicitPluginId=true`.
- Live tests only behaved safely when explicit `pluginId` was passed.

Impact:

- If any UI/API path falls back to `"default"` in this state, wrong-file or wrong-page mutation risk exists.

### 4. Current selected node is not a designer workflow target

Severity: Medium

Observed:

- Current selection in `Agent_skill_test / Page 55` is a single image-backed `RECTANGLE`.
- Auto Layout, spacing, style binding, component instance, and variant workflow tests are not meaningful on that selected node.

Impact:

- Natural-language requests like "선택한 화면 UX/UI 리뷰" may be interpreted as image analysis or limited geometry review, not editable frame review.
- QA must deliberately select fixture frames/components before L-series Designer Workflow tests.

## Improvement Plan

### P0 - Queue lifecycle and timeout cleanup

1. Add cancellation handling when HTTP client disconnects during command-backed routes.
2. Mark orphaned command results as `abandoned` or `unclaimed`, not active pending queue debt.
3. Add runtime metric fields:
   - `orphanedResultTotal`
   - `clientAbortedCommandTotal`
   - `pendingResultOldestMs`
4. Update `/api/runtime-ops` so stale pending results are separately classified from live pending commands.
5. Add regression test:
   - Start `get_node_details` or token export.
   - Abort client request.
   - Let plugin complete command.
   - Assert runtime has no blocking pending queue item and exposes an abandoned-result metric.

### P0 - Streaming validator stability

1. Change `validate-streaming-first.mjs` to wait for a bounded queue-drain grace period before asserting `pendingQueueTotal=0`.
2. Separate failures:
   - command lifecycle failure
   - queue cleanup delayed
   - stale validation session noise
3. For live environments, ignore the validator's own temporary sessions when comparing app live-session counts.
4. Add retry/read-after-delay around runtime parity checks.

### P1 - Token export interactive contract

1. Convert `/api/export-design-tokens` response to immediate artifact job acknowledgement for large files.
2. Stream progress:
   - collection summary read
   - chunk N/M
   - artifact written
   - partial warning if budget exceeded
3. Return a partial report inside the plugin UI instead of leaving the user waiting.
4. Add a hard response budget for UI-initiated token export, with background continuation optional.

### P1 - Designer read-context budget

1. Split `designer/read-context` into:
   - fast read context within 3-5 seconds
   - optional deep detail/token enrichment
   - Codex analysis stage
2. If deep reads exceed budget, return evidence gathered so far and label missing evidence.
3. Ensure the UI shows progressive assistant messages while deep read is still running.

### P1 - Explicit pluginId enforcement

1. In ambiguous session state, block write routes that do not pass explicit `pluginId`.
2. Show current file/page/pluginId in every write confirmation preview.
3. Add tests for "default pluginId refused when activeSessionResolution is ambiguous".

### P2 - Designer Workflow fixture setup

1. Create a dedicated QA fixture page with:
   - Auto Layout card/list fixture
   - text style fixture
   - component instance fixture
   - locked/hidden/masked fixture
2. Add a script to create and clean up fixture nodes.
3. Run L01-L30 against that fixture instead of whichever user node is currently selected.
