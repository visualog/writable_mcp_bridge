# 이미지 분석 기반 화면 구현 개선 정리

## 배경

첨부된 비교 화면 기준으로, 이미지 분석 후 생성된 Figma 화면은 이전보다 요소를 분해하려는 방향은 좋아졌지만 아직 원본 화면의 구조, 스타일, 좌표, 컴포넌트 의미를 충분히 반영하지 못하고 있다.

현재 문제는 단순히 "텍스트가 있는가"보다 더 깊은 수준이다. 원본 이미지에서 어떤 요소가 버튼인지, 행인지, 토글인지, 섹션 구분선인지, 어떤 스타일과 크기를 가져야 하는지까지 인식하고 생성해야 한다.

## 주요 부족점

### 1. 전체 프레임 비율과 시작 위치가 다름

- 구현 화면은 원본보다 폭이 좁고 콘텐츠가 왼쪽으로 몰려 있다.
- 원본은 iPhone 프레임 안에서 좌우 여백이 일정하지만, 구현본은 좌측 여백이 좁고 우측 영역이 과하게 남거나 일부 요소가 잘린다.
- 상단 상태바, 네비게이션, 본문 시작 y 위치가 원본과 조금씩 어긋난다.

### 2. 텍스트 줄바꿈과 그룹 구조가 깨짐

- 원본의 `생활통장`은 한 줄 제목인데, 구현본에서는 `생활통 / 장`처럼 줄바꿈이 발생했다.
- 이는 텍스트 노드의 width가 너무 좁거나 bbox 기반 가로 크기 추정이 잘못된 것이다.
- `케이뱅크 100`, 배지, 계좌 정보 그룹도 원본의 시각적 묶음보다 덜 안정적으로 배치되어 있다.

### 3. 버튼과 행 컴포넌트의 형태가 원본과 다름

- 원본의 쿠폰 행은 흰 배경, 얇은 border, 적당한 radius를 가진 행이다.
- 구현본은 연한 회색 filled card처럼 보여 원본과 컴포넌트 성격이 다르다.
- 하단 버튼들도 원본은 흰 배경에 border가 있는 버튼인데, 구현본은 회색 pill 형태에 가깝다.
- 즉, 역할은 어느 정도 인식했지만 스타일 토큰과 컴포넌트 종류를 잘못 선택하고 있다.

### 4. 색상과 명도 대비가 부정확함

- 원본은 대부분 흰 배경과 아주 옅은 구분선 중심이다.
- 구현본은 섹션 배경, 버튼 배경, 일부 텍스트가 너무 연하거나 회색 블록처럼 처리되어 원본보다 흐릿하다.
- 원본 reference layer가 뒤에 깔린 것처럼 보여 구현 레이어와 원본 이미지가 섞여 보이는 문제도 있다.

### 5. 아이콘과 상태바 재현이 부족함

- 뒤로가기, 편집 연필, 쿠폰 아이콘, chevron, 토글, 하단 브라우저 툴바 아이콘의 형태, 크기, 위치가 아직 단순화되어 있다.
- 특히 토글은 원본에서 우측에 명확히 붙어 있고 `ON` 텍스트와 knob가 정돈되어 있지만, 구현본에서는 잘리거나 겹쳐 보인다.

### 6. 섹션 간 간격과 구분선 흐름이 다름

- 원본은 쿠폰 카드 아래에 굵은 section separator가 있고, 이후 섹션 제목, 행, 버튼이 일정한 rhythm으로 내려간다.
- 구현본은 간격이 어느 정도 맞아졌지만 separator 두께, 섹션 시작 y 위치, 버튼 간격이 원본과 다르다.
- `케이뱅크 연결 관리` 행 오른쪽 chevron도 위치가 너무 끝으로 밀리거나 흐리게 보인다.

## 개선 방향

### 1. bbox 검증을 텍스트뿐 아니라 컴포넌트 단위로 강화

현재는 문구와 좌표가 어느 정도 맞는지 보는 수준이다. 앞으로는 `row`, `button`, `toggle`, `section`, `toolbar` 같은 role별 bbox 크기와 위치도 검사해야 한다.

예를 들어 버튼 role이면 원본 bbox의 `x`, `y`, `width`, `height`, `radius`, `border`와 생성 노드가 일정 오차 안에 있어야 한다.

### 2. 원본 스타일 분류를 더 세분화

다음과 같은 컴포넌트 스타일을 구분해야 한다.

- `filled_card`
- `outlined_button`
- `plain_row`
- `section_separator`
- `toggle`
- `browser_toolbar`

현재는 여러 요소가 회색 filled pill/card로 뭉뚱그려지는 경향이 있다.

### 3. 텍스트 노드 최소 폭과 줄바꿈 방지 규칙 추가

- roleMap label이 원본에서 한 줄로 보이는 경우, 생성 텍스트 width가 label 길이에 비해 너무 작으면 실패 처리해야 한다.
- `생활통장` 같은 짧은 제목이 줄바꿈되면 품질 실패로 봐야 한다.
- 텍스트 bbox와 생성 텍스트 노드 width를 함께 비교해야 한다.

### 4. 원본 reference layer와 구현 layer 분리

- reference image는 비교용으로만 낮은 opacity 또는 별도 위치에 두어야 한다.
- 최종 구현 화면 위에 reference layer가 시각적으로 섞이지 않도록 해야 한다.
- 현재 구현본은 reference가 뒤에 남아 화면이 흐릿해 보일 가능성이 있다.

### 5. role별 스타일 힌트를 prompt와 validator에 추가

role 인식이 실제 Figma 속성까지 이어져야 한다.

| Role | 기대 스타일 |
| --- | --- |
| `outlined_button` | 흰 fill, 연한 stroke, radius 4~8 |
| `coupon_row` | 흰 fill, stroke, left icon, right chevron |
| `toggle_on` | green track, white knob, right aligned |
| `section_separator` | full-width light gray band |
| `browser_toolbar` | fixed bottom toolbar, icon buttons |

### 6. 생성 후 시각 비교 점수 도입

생성 후 원본과 구현본의 차이를 자동으로 요약하는 품질 리포트가 필요하다.

비교 항목:

- 주요 bbox 차이
- 텍스트 위치 차이
- 텍스트 줄바꿈 여부
- 색상 차이
- 컴포넌트 수 차이
- role별 스타일 일치 여부

이 점수를 자동 재시도 조건으로 연결하면, "생성은 됐지만 부족한 화면"을 통과시키지 않을 수 있다.

## 우선순위 제안

1. 텍스트 줄바꿈 실패 감지
2. role별 bbox 크기/위치 검증
3. outlined button, row, toggle, separator 스타일 분류 추가
4. reference layer가 구현 결과를 흐리게 만들지 않도록 분리
5. 생성 후 품질 리포트와 자동 재시도 연결

## 결론

현재 문제는 요소 인식 자체가 전혀 안 되는 상태는 아니다. 다만 원본의 컴포넌트 타입, 스타일, 정확한 bbox, 줄바꿈 여부까지 구현 품질 기준에 충분히 반영되지 않은 상태다.

다음 개선은 텍스트 커버리지보다 한 단계 더 들어가서 **role별 컴포넌트 fidelity 검사**를 추가하는 방향이 맞다.
