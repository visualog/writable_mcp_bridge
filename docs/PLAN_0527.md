# Xbridge 공식 가이드 준수 + Buddy식 작업 세션 개선 계획

## Summary
- 현재 핵심 결함은 “읽기 전체 실패”가 아니라, `export_design_tokens`가 Figma 플러그인 main thread 안에서 300초 만료되는 구조입니다. `ack_to_complete` 병목이 확인됐으므로 전체 변수 export를 단일 명령으로 처리하는 방식을 폐기합니다.
- 우선순위는 `공식 Figma 플러그인 가이드 준수 → 긴 작업 chunk/job화 → Buddy식 진행 로그/결과 UX → DS Variable 바인딩 고도화` 순서로 잡습니다.
- 공식 문서 대조 기준: Figma plugin manifest의 `documentAccess: "dynamic-page"`, network access 정책, Variables API 사용 방향을 반영합니다.

## Key Changes
- **Manifest / Dynamic Page 대응**
  - `figma-plugin/manifest.json`에 `"documentAccess": "dynamic-page"` 추가.
  - `code.js`에서 전체 파일 탐색성 호출은 기본적으로 현재 페이지/명시 대상만 읽도록 제한.
  - Variables/Styles/Library 조회는 async API 우선으로 통일하고, sync local variable/style getter는 dynamic-page 모드에서 직접 사용하지 않도록 정리.

- **변수 JSON Export 재설계**
  - 기존 `export_design_tokens` 단일 명령은 호환용 wrapper로 남기되 내부는 chunk/job 방식으로 변경.
  - 새 플러그인 read 명령:
    - `get_variable_collections_summary`: 컬렉션 id/name/mode/variable count만 빠르게 반환.
    - `export_design_tokens_chunk`: `{ collectionId, cursor, limit, includeAliases, includeResolvedValues }` 단위로 변수 일부만 반환.
  - 서버는 `/api/export-design-tokens`에서 chunk 명령을 순차 실행해 JSON artifact를 생성하고, 응답에는 `{ ok, filePath, variableCount, collectionCount, elapsedMs, warnings }`만 반환.
  - 기본 저장 위치는 `/private/tmp/xbridge-token-exports/<fileName>-<timestamp>.json`로 두고, repo tracked 파일은 만들지 않습니다.

- **Buddy식 작업 세션 UX**
  - AI 디자이너 요청은 “Codex 응답 대기”가 아니라 `task session`으로 표시.
  - 진행 로그는 단계별로 노출:
    - `변수 컬렉션 읽기`
    - `0.1. primitives 222개 처리`
    - `alias/resolved value 계산`
    - `JSON 파일 저장`
    - `완료 요약 생성`
  - 선택/대상 컨텍스트를 입력창 주변에 attachment처럼 표시: 현재 파일, 페이지, 선택 노드 수, design-system context 상태.
  - 긴 read/export 작업은 Codex 요약 호출을 생략하고 deterministic summary를 먼저 반환합니다. Codex는 후속 설명이 필요할 때만 사용합니다.

- **DS Variable Binding 고도화**
  - `ds-registry` 토큰은 hex literal만 쓰는 구조에서 `variableName` 또는 `variableKey` 참조를 허용하는 구조로 확장.
  - 레이아웃 생성 시 literal fill/text 값보다 Figma Variable Binding을 우선 적용.
  - 결과 요약에 `literal`, `bound variable`, `missing variable`, `fallback` 수를 표시.

## Test Plan
- **정적/단위 테스트**
  - manifest에 `documentAccess: "dynamic-page"`가 있는지 검사.
  - 변수 export 경로가 sync `getLocalVariables()`에 의존하지 않는지 계약 테스트 추가.
  - chunk export가 cursor/limit을 지키고 alias/resolved value 옵션을 보존하는지 테스트.
  - `/api/export-design-tokens`가 JSON artifact 경로와 count summary를 반환하는지 서버 테스트.

- **통합/수동 검증**
  - FDS v2.0에서 컬렉션 7개, 총 548개 변수 기준으로 export가 300초 만료 없이 완료되는지 확인.
  - 생성된 JSON에 `collections`, `variables`, `valuesByMode`, `aliasesByMode`, `resolvedValuesByMode`, `meta`가 포함되는지 확인.
  - UI에서 “읽기 실행 실패: Codex 응답 timeout” 대신 단계별 진행 로그와 최종 파일 경로가 표시되는지 확인.
  - dynamic-page 적용 후 `get_selection`, `get_metadata`, `search_instances`, `search_design_system`, `get_variable_defs` 회귀 테스트.

## Assumptions
- 우선 목표는 Figma Community 배포보다 로컬 개발 플러그인의 안정화입니다. 따라서 `networkAccess.allowedDomains`는 유지하고, 로컬 브리지는 `devAllowedDomains`에 둡니다.
- 변수 export 결과는 채팅 메시지에 대형 JSON을 직접 넣지 않고 파일 artifact로 저장합니다.
- Buddy 벤치마킹은 원격 서버 복제가 아니라 `작업 세션 + 스트리밍/진행 로그 + 선택 컨텍스트 attachment + 결과 요약` 패턴만 Xbridge 방식으로 적용합니다.
