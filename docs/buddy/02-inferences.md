## 엔진 구조 추정
- Buddy는 단순한 채팅 응답 생성기보다 `Figma action agent`에 가깝습니다.
  근거:
  `Read from ...`, `Created Figma node` 같은 실행 로그가 직접 관찰됨.

- 자연어를 바로 Figma API 호출로 연결하지 않고, 중간 실행 표현을 거칠 가능성이 큽니다.
  근거:
  디자인 시스템 카탈로그와 중간 모델 추출을 시사하는 문자열이 관찰됨.

- 선택 정보 외에 컴포넌트, 변수, variants, auto layout 정보를 함께 수집해 모델 컨텍스트에 넣을 가능성이 큽니다.
  근거:
  Buddy 표면 프롬프트가 variant 생성, 레이아웃 정리, 스타일 참조를 전제로 함.

## 백엔드 구조 추정
- Buddy는 로컬 전용보다는 클라우드 기반 추론 계층을 둘 가능성이 큽니다.
  근거:
  메시지 제한, 업그레이드 유도, 외부 API 경로 흔적이 관찰됨.

- 모델 종류는 외부 상용 모델을 포함한 서버측 추론일 가능성이 큽니다.
  근거:
  유료 크레딧 구조와 직접적인 캔버스 액션 범위를 동시에 제공함.

## 실행 루프 추정
- 실행 루프는 대체로 `읽기 -> 계획 -> 생성/변경 -> 검증 -> 요약`으로 구성될 가능성이 큽니다.
  근거:
  읽기 로그, node 생성 로그, 완료 요약, 후속 액션 제안이 모두 보임.

- 결과 제안과 후속 액션은 별도 보조 계층이 아니라 실행 엔진의 일부일 가능성이 큽니다.
  근거:
  결과 요약 뒤 바로 후속 액션 버튼이 이어지는 구조가 반복적으로 관찰됨.

## 제품 전략 추정
- Buddy의 경쟁력은 모델 자체보다 `디자인 시스템 인지 + 캔버스 액션 + 작업 콘솔 UX`의 결합에 있습니다.
  근거:
  공개 설명과 실제 사용 흐름 모두 채팅보다 실행과 상태 노출이 중심임.
