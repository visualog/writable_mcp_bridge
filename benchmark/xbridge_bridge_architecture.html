Xbridge · v0.5.65

Xbridge 현재 구조도

현재 브리지는 `Figma 플러그인 UI`와 `브리지 서버`, `로컬/원격 AI 제공자`, `Figma Canvas` 사이를 연결하는 구조입니다. 아래 다이어그램은 지금 코드베이스 기준의 실제 계층과 주요 데이터 흐름을 한 장으로 정리한 것입니다.

Primary Surface
Figma 플러그인 UI에서 요청을 받고, 브리지 서버를 통해 Figma canvas와 AI 제공자 사이를 조율합니다.
Current Strong Path
selection-first read plan과 Context Model v1 조립은 비교적 안정적이고, inspect_selection은 AI preflight를 우회합니다.
Current Friction
인스턴스 설명 품질, generic fallback, UI report와 suggestion bundle의 표현 일관성이 아직 정교하지 않습니다.

Figma Plugin UI (ui.html)

역할

사용자가 요청을 입력하고, 작업이 어떻게 진행되는지 확인하는 화면입니다.

어떤 AI를 쓸지 고르고, 결과를 이해하기 쉽게 보여주는 역할을 합니다.

주요 통신 경로

Bridge Server (Node · port 3846)

역할

플러그인 화면, Figma 파일, AI 모델 사이에서 요청을 중간에서 정리하고 연결합니다.

현재 어떤 화면이 살아 있는지 확인하고, 요청을 올바른 곳으로 보내는 역할을 합니다.

핵심 런타임

구조를 설명해 달라는 요청은 불필요한 단계를 줄이고, 먼저 읽은 내용을 빠르게 보여주도록 설계했습니다.

Designer Engine Layer

핵심 흐름

사용자 요청이 들어오면, 먼저 무엇을 하려는 요청인지 이해합니다.

그다음 Figma에서 필요한 정보를 읽고, AI가 이해하기 쉬운 형태로 정리한 뒤 다음 행동을 만듭니다.

Intent & Read Routing
  • selection-first
  • bounded detail
  • asset lookup second
Context Model v1
  • meta · target · selection
  • focusedNode · structure
  • designSystem · readMeta
Suggestions / Preview
  • findings · recommendations
  • applyActions
  • summaryText

Figma Plugin Session / Canvas

역할

실제로 Figma 화면 안의 레이어, 텍스트, 컴포넌트를 읽고 바꾸는 곳입니다.

브리지가 판단한 작업을 실제 디자인 파일에 반영하는 실행 구간입니다.

읽기
get_metadata get_node_details get_instance_details get_component_variant_details get_variable_defs search_design_system
쓰기
bulk_update_texts update_node set_variant_properties

AI Provider Layer

역할

사용자 요청을 이해하고, 문구를 만들거나 구조를 설명하는 실제 AI 모델이 있는 구간입니다.

로컬 모델이나 외부 AI 서비스를 상황에 맞게 연결해 사용하는 부분입니다.

연결 대상
Ollama 127.0.0.1:11434/v1 OpenAI NVIDIA LM Studio Custom
현재 특징

텍스트 변경은 모델 호출, inspect_selection은 가능하면 AI를 우회합니다.

현재 병목은 인스턴스 설명 품질과 generic fallback입니다.

주요 실행 흐름
1. 사용자 요청 입력
2. 세션 / pluginId 결정
3. read plan 실행
4. contextModel 조립
5. AI 또는 바로 응답
inspect_selection은 AI preflight를 건너뛰고 읽기 결과 중심으로 반환합니다.
계층 해석

UI 레이어

사용자 입력, 진행 로그, AI 설정, 세션 상태를 보여주는 표면입니다.

브리지 런타임

세션, heartbeat, stale recovery, `pluginId` 선택을 책임집니다.

엔진 레이어

intent 분류, read plan, Context Model v1, suggestions-v2를 만듭니다.

Figma canvas

실제 읽기/쓰기 명령은 플러그인 session이 canvas에 대해 수행합니다.

AI provider

Ollama 로컬 모델과 원격 API 제공자가 텍스트 생성/분류를 담당합니다.

현재 강한 지점
세션 복구와 active plugin 선택

`default` 대신 실제 selection이 있는 live page 세션을 우선 고르는 보정이 들어가 있습니다.

Context Model v1

selection / focusedNode / structure / designSystem / readMeta를 한 객체로 조립합니다.

inspect_selection 분기

구조 읽기 요청은 AI preflight를 우회하고 read 결과 중심으로 바로 응답합니다.

현재 병목과 해석
인스턴스 설명 품질

읽기는 성공해도 UI 요약기가 `variant / override`를 일반 구조 요약으로 축약하는 경우가 있습니다.

UI와 엔진의 경계

같은 inspect 요청인데도 `UI report`와 `suggestion bundle` 중 어떤 문장이 먼저 보이는지 일관성이 부족합니다.

로컬 모델 체감 품질

직접 Ollama와 대화할 때보다 브리지 경로에서 generic한 결과가 더 자주 보일 수 있습니다.

이 구조도는 `Buddy`를 그대로 복제하려는 문서가 아니라, 현재 xbridge가 어떤 계층으로 움직이는지 팀이 빠르게 공유하고 디버깅하기 위한 “현재 상태 지도”입니다.
